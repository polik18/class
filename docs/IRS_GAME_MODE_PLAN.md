# IRS 闖關遊戲模式計畫（音效、音樂、刺激感）

- 狀態：G1～G5 完成並通過自動化測試（2026-11-23）；G6 試教待老師在班上進行，手冊見 `docs/IRS_GAME_TRIAL_GUIDE.md`
- 日期：2026-11-23
- 目標：把即時問答從「按鈕遙控器」升級成有節奏、有音樂、有排行榜的課堂競賽，體驗接近 Kahoot 這類遊戲式問答。
- 原創原則：只借鏡「題目上大螢幕、手機只按色塊、倒數＋速度計分＋排行榜」這類通用玩法；**音樂、音效、配色、圖形、角色、名稱全部原創**，不使用任何 Kahoot 的素材、配樂或外觀。

## 1. 現況研究

| 項目 | 現況 | 問題 |
|---|---|---|
| 題目內容 | 老師口頭出題，系統只送題型（ABCD／OX／投票／搶答／文字） | 投影幕上沒有題目，學生要邊聽邊按 |
| 正確答案 | 不存在 | 無法判對錯、無法計分 |
| 倒數計時 | 沒有，老師手動「停止作答」 | 沒有緊張感，節奏全靠老師 |
| 計分／排行 | 只有作答分布長條圖與搶答順序 | 沒有個人分數、連對、名次 |
| 音效 | 學生收到題目時一聲「嗶」（共用計分板的 `playScoreSound`） | 單薄、沒有回饋層次 |
| 音樂 | 沒有 | 沒有氣氛 |
| 學生畫面 | 四個漸層按鈕（ABCD 字母） | 只靠顏色＋字母，色盲不友善；按完沒有刺激回饋 |
| 題庫 | 沒有 | 每次上課都要重想題目 |

可沿用的基礎：
- 混合連線＋Swarm 中繼、答案 ACK 去重（作答不會遺失或重複計分）。
- IndexedDB 保存房間、題目與答案（`irs-persistence.js`）。
- 全站已有 Web Audio 合成音效（鐘聲、抽籤、計時器）與 `audioCtx` 延遲建立機制、全域靜音 `appState.isMuted`。
- 投影模式、Polik Neo 外觀、PWA 離線。

## 2. 體驗設計：一回合的節奏

```text
大廳 ──▶ 題目預告 ──▶ 作答倒數 ──▶ 揭曉 ──▶ 排行榜 ──▶（下一題）… ──▶ 頒獎台
Lobby    3 秒          5～60 秒      4 秒     5 秒                      終局
```

| 階段 | 投影幕（老師端） | 學生手機 | 聲音（投影幕喇叭） |
|---|---|---|---|
| 大廳 | 大 QR Code、房號、加入名字以泡泡飛入、人數計數 | 輸入暱稱、選頭像、「等待開始」動畫 | 輕快大廳循環樂；每位學生加入「啵」一聲 |
| 題目預告 | 題號、題目文字、圖片，3 秒進度條 | 「準備！」＋題型圖示 | 上升音效（riser） |
| 作答倒數 | 題目＋四個色塊選項、倒數圓環、已作答人數 | 四個大色塊（顏色＋形狀＋字母） | 緊張循環樂，最後 5 秒加速＋滴答 |
| 揭曉 | 正確選項放大發光、其餘淡出、分布長條圖 | 全螢幕「答對！+870」或「差一點」，顯示連對火焰 | 答對和弦／答錯低音（各裝置只播自己的） |
| 排行榜 | 前 5 名名條滑動換位、名次上升箭頭 | 「你目前第 7 名，距前一名 120 分」 | 鼓聲滾奏＋重音 |
| 頒獎台 | 第 3→2→1 名依序升起、彩帶 | 自己的總排名與答對數 | 號角式勝利樂段 |

設計重點：
1. **題目只顯示在投影幕**，手機只顯示色塊。學生必須抬頭看螢幕，教室有一起看的感覺；也讓網路只傳極小的訊息（不傳圖片），完全符合 Swarm 中繼 8 KiB 上限。
2. **選項用「顏色＋形狀＋字母」三重編碼**（例如：靛藍◆A、翠綠●B、琥珀▲C、玫紅■D），色盲與黑白投影也能辨識。形狀與配色採 Polik 主色系，原創圖形。
3. **學生手機預設只開音效、不開音樂**：30 支手機同時放音樂會很吵，背景音樂只由投影幕播放。
4. **老師永遠有控制權**：可暫停、跳過、提早結束倒數、隱藏排行榜（避免排名壓力），每個階段都可手動推進。

## 3. 計分與刺激感

### 3.1 速度計分（含防作弊）

- 答對基本分 500，速度加成最高 500：`分數 = 500 + 500 × (1 − 作答秒數 ／ 限時)`，四捨五入到 10。
- 作答秒數以**學生裝置收到題目到按下的時間**計算，消除網路延遲（中繼多一跳的學生不吃虧）。
- 防作弊：老師端以「收到答案的時間 − 發題時間」做上限，學生回報的秒數不可大於此值，也不可小於（老師端時間 − 該路徑來回延遲 × 2）。異常一律以老師端時間計。
- 每題每人只計第一份答案（沿用既有 `(roomId, questionId, senderId)` 去重）。

### 3.2 連對與加成

- 連對 3 題起出現「🔥 連對」標記，每多一題 +100（上限 +500）。
- 答錯或未作答時連對歸零，但**不扣分**（國小課堂避免負面感受）。
- 可選「雙倍分數題」：老師在題庫勾選，預告階段顯示金色標記與特別音效。

### 3.3 名次回饋

- 排行榜只公開前 5 名；其餘學生只在自己手機看到名次與「距前一名多少分」。
- 「進步最多」小獎：每題結束顯示名次上升最多的人（給中後段學生動機）。
- 老師可切換「團隊模式」：沿用抽籤機的分組，名次以小組平均分計，直接連動計分板。

## 4. 聲音設計（全部原創、Web Audio 即時合成）

### 4.1 為什麼用程式合成，不放音樂檔

- **零版權風險**：旋律、和弦進行、音色都由程式產生，是本專案原創作品。
- **極小**：整套引擎預估 15～25 KB，不需下載 MP3；離線（PWA）也能播。
- **可隨遊戲狀態變化**：倒數剩越少，節奏越快、音高越高；排行榜換位時同步打點。這是固定 MP3 做不到的。
- 進階選項：老師可上傳自己的 MP3 取代大廳音樂（沿用鐘聲「自訂音檔」的現成機制）。

### 4.2 音樂曲目（新模組 `js/pro/irs-sound.js`）

| 曲目 | 用途 | 設計 |
|---|---|---|
| 大廳 Lobby | 等待加入 | 112 BPM，大調四和弦循環、輕柔貝斯與 hi-hat，8 小節無縫循環 |
| 思考 Think | 作答倒數 | 128 BPM，小調低音脈衝＋琶音；剩 10 秒加入 snare，剩 5 秒升半音並加速到 140 BPM |
| 揭曉 Reveal | 揭曉答案 | 0.6 秒上行刷奏＋重音 |
| 排行 Board | 排行榜 | 定音鼓滾奏 1.5 秒＋鈸 |
| 頒獎 Podium | 終局 | 8 小節號角式主題（原創旋律），第 1 名升起時落在主和弦 |

所有曲目用同一個「16 步音序器」產生：Lookahead 排程（每 25 ms 預排 100 ms 內的音符），避免主執行緒忙碌時節拍不穩。

### 4.3 音效清單

| 音效 | 觸發 | 播放裝置 |
|---|---|---|
| join-pop | 學生加入 | 投影幕 |
| riser | 題目預告 | 投影幕 |
| tick／tick-urgent | 最後 5 秒每秒 | 投影幕 |
| time-up | 時間到 | 投影幕 |
| tap | 學生按下選項 | 學生手機（觸覺回饋 `navigator.vibrate(15)`） |
| correct | 答對 | 學生手機、投影幕揭曉時 |
| wrong | 答錯 | 學生手機（溫和低音，不刺耳） |
| streak | 連對 3 題以上 | 學生手機 |
| rank-up | 名次上升 | 學生手機 |
| podium-1/2/3 | 頒獎台升起 | 投影幕 |

### 4.4 混音與教室友善

- 主音量、音樂、音效三個獨立滑桿；設定記在 localStorage。
- 進入揭曉或老師說話時：音樂自動降低 60%（ducking），老師按「暫停」時淡出。
- 壓縮器（DynamicsCompressor）＋限幅，避免投影機喇叭破音。
- 尊重全域靜音與 `prefers-reduced-motion`（動畫減量時仍保留音效）。
- iOS Safari 需使用者手勢才能出聲：學生按「加入」時順便解鎖音訊。

## 5. 視覺與質感

- **倒數圓環**：SVG 圓環＋大數字，剩 5 秒轉為玫紅並脈動；數字使用 JetBrains Mono 等寬字避免跳動。
- **答案揭曉**：正確選項放大 1.08 倍並加光暈掃過；錯誤選項降到 30% 透明度；長條圖由下往上生長（彈簧緩動）。
- **排行榜換位**：FLIP 動畫（先記位置、再過渡），名條上下滑動、分數數字滾動。
- **頒獎台**：三層台座依序升起，原創 Canvas 彩帶粒子（限 150 顆，低階電腦自動減量）。
- **學生回饋畫面**：答對時全螢幕翠綠漸層＋分數彈出；答錯時靛藍（不用紅色，降低挫折）並顯示正確答案。
- 全部沿用 Polik Neo 色系與投影模式；動畫以 CSS transform／opacity 為主，確保教室舊電腦也流暢。

## 6. 題庫與老師流程

- **題庫編輯器**：題目文字（≤ 120 字）、選項 2～4 個（各 ≤ 60 字）、正確答案（可多個）、限時（5／10／20／30／60 秒）、雙倍分數、可選圖片。
- **儲存**：題庫存在老師瀏覽器 IndexedDB；可匯出／匯入 JSON 分享給其他老師；也可從 CSV（Excel）匯入。不上傳雲端。
- **圖片**：只在投影幕顯示，以 data URL 存入題庫（壓到 ≤ 300 KB），不經網路傳給學生。
- **快速出題**：保留現有「口頭出題＋按鈕」模式作為「自由模式」，遊戲模式是另一個入口，互不影響。
- **結束後**：成績 CSV 匯出（姓名、各題對錯、作答秒數、總分、名次），沿用資料管理中心。

## 7. 技術設計

### 7.1 新模組

```text
js/pro/irs-sound.js   音序器、合成樂器、曲目、音效、混音（不依賴其他模組）
js/pro/irs-game.js    遊戲狀態機、計分、排行、題庫存取
js/pro/irs-stage.js   投影幕各階段畫面與動畫（大廳、題目、揭曉、排行、頒獎）
```

### 7.2 遊戲狀態機（老師端為唯一權威）

```text
LOBBY → PREVIEW → ANSWERING → REVEAL → LEADERBOARD → (PREVIEW … ) → PODIUM → END
```

- 每次換階段廣播一則小訊息（< 1 KB），例如：
  - `game.preview { qIndex, total, qType, options: 4, timeLimit, double }`（不含題目文字與正確答案）
  - `game.reveal { questionId, correct: ['B'], yourScore?, yourRank? }`：每位學生的個人分數走單播，經既有 ACK／Swarm 簽章路徑。
- 學生的答案仍用既有 `answer` 訊息，多帶 `elapsedMs`；ACK、重送、去重不變。
- 正確答案**揭曉前不送到學生裝置**，避免有人看封包作弊。
- 斷線重連：學生重新加入時，老師端依狀態機補送目前階段與個人累計分數。

### 7.3 效能與容量

- 每題流量：學生上行 1 則答案、下行 3～4 則階段訊息，與現有 IRS 同級；60 人 Swarm 實測已通過同等訊息量。
- 揭曉時的個人結果採批次單播（每 20 人一批、間隔 50 ms），避免老師端瞬間送出 60 則。
- 音樂只在投影幕播放，不佔網路。

## 9. 風險與決策點

1. **競賽壓力**：預設隱藏後段名次、不扣分、提供「進步最多」；老師可整場關閉排行榜（只保留答對回饋）。
2. **教室音量**：音樂只在投影幕；提供一鍵「安靜模式」（只保留時間到與揭曉音效）。
3. **作答秒數可被竄改**：已用老師端時間做上下限；國小情境下風險低，不做更重的防護。
4. **iOS 靜音開關**：iPhone 側邊靜音開啟時網頁無聲，學生手機以震動＋畫面回饋為主，不依賴聲音。
